# サービスコンセプト・情報設計・UI/UX再評価（2026-10-12）

## 結論

積立タイムマシンの独自価値は「任意利回りの将来予測」ではなく、商品設定後の公式月次実績を円ベース・同一条件で再現し、欠損や設定前を補完せず比較できることにある。推奨構成は **B：積立実績シミュレーター中心型** を本体、**C：一次情報を検証できる投資データ研究所型** を信頼レイヤーとする組み合わせ。記事・ランキング・図鑑は主役ではなく、条件選択と結果解釈を助ける補助層に置く。

AdSense不承認との有力な関連仮説は、技術エラーよりも、トップと96 URL全体が「検証ツール」より「ランキングを含む投資情報ポータル」に見え、独自のデータ検証価値が埋もれていること。承認可否は保証できない。

## 8視点レビュー

1. AdSense品質: 一次情報・独自計算は強い。テンプレート間の役割重複とトップのリンク集化が弱点。
2. プロダクト戦略: 「実績を再現して比較する」ジョブは成立。入力→結果→比較→根拠を一本道にする。
3. スマホUI/UX: タップ領域は概ね良好。主入力までのスクロール、横カード、比較条件の引継ぎが課題。
4. 情報設計: Simulation / Compare / Fund / Guide / Article / Ranking / From の名称と次行動を明確に分ける。
5. SEO: 比較ページが検索流入の主力。URL統合はGSC実測と承認なしに行わない。
6. 金融信頼性: A/G境界、設定前拒否、台帳は強い。読者向け日本語と結果近接の説明を改善する。
7. ブランド・コピー: 利益額・ランキングより「検証可能性」を前面にする。将来優位を示唆しない。
8. Web事業: 広告PVより、シミュレーション完了率、比較率、出典確認率、共有・再訪を先行KPIにする。

## 情報階層（96 URL）

- 主行動: Home → Simulation → Result → Compare / Share
- 信頼確認: Result / Fund → Data Sources → 一次情報
- 商品理解: Fund → 同商品を設定したSimulation → Compare
- 検索入口: Guide / Article → 固有の問いへの回答 → 検証条件を引き継いだSimulation
- 探索補助: Ranking / From / Hub → 固定条件を明示 → 条件変更

Landing/Fund、Compare/Article、From、Ranking、Hubの統合・redirect・canonical・noindexは、このスプリントでは変更しない。既存検索流入と被リンクを確認し、別途承認されたURLマッピングで行う。

## 実装した安全な改善

- トップの主CTAを検証例より前へ移動し、商品・開始月/月額・結果確認の3ステップを表示。
- 主コピーを「商品・開始月・月額から過去の積立結果を再現」へ明確化。
- タブ遷移時にページ先頭へ戻し、入力途中から表示される迷いを解消。
- 単一商品の結果から比較へ、開始年月と月額を引き継ぐ。
- 期間説明の旧固定終端（2025年6月）をSSOTの終了月参照へ変更。
- Data Sourcesの英語内部用語を日本語へ翻訳し、月次データ・費用・欠損処理を明確化。

## 今回変更しない事項

- URL、title、H1、canonical、index/noindex、sitemap
- シミュレーション計算、月次データ、品質区分
- PC向け全面2カラム化、ナビゲーション全面改修
- Landing/FundやCompare/Articleの統合

これらは検索影響または大規模な見せ方変更を伴うため、別スプリントの承認事項とする。
